# Hospitality Flow Pilot Validation

Lightweight documentation system for pilot sessions. Use it to capture whether Hospitality Flow is understandable, useful, trusted and time-saving — without changing product priorities based on one-off preference.

## Files

| File | Purpose |
|---|---|
| `PILOT_VALIDATION_TEMPLATE.md` | One copy per pilot session |
| `UX_BACKLOG.md` | Product improvement ideas held outside the active sprint |
| `CUSTOMER_INSIGHTS.md` | Direct quotes, behaviour and buying signals |

## Workflow

1. Copy `PILOT_VALIDATION_TEMPLATE.md` for each session.
2. Observe the participant using HF with minimal guidance.
3. Record direct evidence.
4. Transfer small improvements to `UX_BACKLOG.md`.
5. Transfer direct quotations and behaviour to `CUSTOMER_INSIGHTS.md`.
6. Review evidence after every three pilot sessions.
7. Select the next sprint from repeated, high-impact findings.

## Session filename format

```
YYYY-MM-DD-hotel-role-shift.md
```

Example:

```
2026-08-05-zetter-night-manager-night.md
```

Suggested location for completed session notes:

```
docs/pilot-validation/sessions/
```

## Principles

- Prefer repeated pilot evidence over personal preference.
- Keep quotes close to the participant’s wording.
- Separate observation from interpretation.
- Never record sensitive guest information.
- Do not claim time saved unless observed or estimated by the participant.
- No backlog item becomes a sprint automatically.
